# Claude Desktop Project Bundle Guide

Load this reference whenever generating, refreshing, or scaffolding a Claude Desktop **Project Knowledge bundle** (the directory-format upload target for a Claude Desktop Project's Knowledge panel).

Project bundles are **regular directories** holding flat-laid markdown / CSV / etc. — **NOT** `.zip` archives. The `.zip` format is reserved exclusively for Skill uploads (see `claude-desktop-packaging-guide.md` for those).

---

## Architectural overview

**Separation of concerns:**

| Concern | Owner | Where it lives |
|---|---|---|
| **Engine** — the bundle-generation procedure (mkdir, copy, flatten, rename, emit auto-README) | `/instruction-creator` (this skill) | This guide + general workflow knowledge |
| **Recipe** — what files belong in the bundle for a specific Project, plus the paste-ready Custom Instructions text | The specific skill backing the Project (e.g. `/medical`) | `references/cd-project-recipe.md` inside that skill |
| **Output** — the materialised bundle directory | Disposable — regenerated on demand | `~/.claude/claude-desktop-projects/<project>/` (universal default) OR `~/Obsidian/memory-bank/_projects/<project>/` (Henry's personal override) |

This split means: any skill that backs a Claude Desktop Project carries a single small recipe file; the generation logic lives once in `/instruction-creator`; the output is reproducible and never committed to the skill's source.

## Recipe file schema

Every skill that backs a Claude Desktop Project keeps **one file** at `references/cd-project-recipe.md` with exactly three sections:

```markdown
# Claude Desktop Project Recipe — <skill-name>

## Custom Instructions

(Full paste-ready text. Becomes `<skill-name>-project-instructions.md` in the bundle output dir. Written in second-person "You are ..." voice addressed to the Claude Desktop Project. This is the exact text the user will paste into Claude Desktop → Project → Custom Instructions.)

## File Manifest

| Source path (relative to skill root) | Target filename (in bundle dir) | Notes |
|---|---|---|
| references/foo.md | foo.md | |
| references/tests/README.md | tests-README.md | Renamed to avoid collision |
| references/imaging/README.md | imaging-README.md | Renamed to avoid collision |
| templates/bar.csv | bar.csv | |

(Source paths are relative to the skill's root directory — i.e. starting from `~/.claude/skills/<skill-name>/`. Targets are the flat filenames inside the output bundle dir. When two source files would collide on flatten — e.g. `tests/README.md` + `imaging/README.md` both become `README.md` — rename one or both at this stage.)

## Sync Log

| Date | Trigger | Notes |
|---|---|---|
| YYYY-MM-DD | Initial recipe creation | Migrated from legacy project-desktop/ subdir |
| YYYY-MM-DD | Refresh — added foo.md | Knowledge file added |
```

The Sync Log lives inside the recipe so it travels with the skill in git — record-of-truth for what was uploaded and when.

## Generation procedure

When the user asks to (re)generate a Project bundle for skill `<S>`:

1. **Load** the recipe at `~/.claude/skills/<S>/references/cd-project-recipe.md`.
2. **Resolve output dir** — universal default is `~/.claude/claude-desktop-projects/<S>/`; check `~/.claude/overrides/skills/instruction-creator.md` for a personal override (Henry's machine routes to `~/Obsidian/memory-bank/_projects/<S>/`).
3. **Create** the output dir: `mkdir -p <output_dir>`.
4. **Clean** prior bundle contents (regeneration is destructive): `rm -f <output_dir>/*.md <output_dir>/*.csv` (preserve any subdirectories user may have added).
5. **Write** the Custom Instructions section to `<output_dir>/<S>-project-instructions.md` (filename pattern: `<skill-name>-project-instructions.md`).
6. **For each row** in the File Manifest: `cp ~/.claude/skills/<S>/<source> <output_dir>/<target>`. The flatten + rename is implicit in the target column.
7. **Emit** an auto-generated `<output_dir>/README.md` with build date, file count, and a pointer back to the source recipe. Example template:
   ```markdown
   # <S> Claude Desktop Project Bundle

   **Auto-generated by `/instruction-creator` on YYYY-MM-DD.** Regenerated from the canonical recipe at `~/.claude/skills/<S>/references/cd-project-recipe.md`.

   ## Contents
   - 1 × Custom Instructions file: `<S>-project-instructions.md`
   - N × knowledge files (.md / .csv) — flat at this directory root

   ## To refresh
   Run `/instruction-creator` together with `/<S>` and ask to rebuild the Project bundle. This README is regenerated each time — do not edit it directly.

   ## Sync history
   See the **Sync Log** section in the source recipe.
   ```
8. **Report** to the user: bundle ready at `<output_dir>`; total entries; suggested next action (drag the directory's contents into Claude Desktop → Project → Knowledge panel).

## Cross-skill invocation pattern

Generating a Project bundle is a two-skill collaboration:

| When user says... | Load... | Then... |
|---|---|---|
| "rebuild the medical project bundle" / "refresh /medical's CD-P bundle" / "generate the medical project knowledge dir" | `/instruction-creator` (engine) + `/medical` (recipe owner) | Execute the procedure above with `<S> = medical` |
| "create a new Claude Desktop Project for skill X" | `/instruction-creator` + `/X` | First check whether `~/.claude/skills/X/references/cd-project-recipe.md` exists; if not, scaffold it from the template above by reading the skill's existing references/ + templates/ + SKILL.md and proposing a manifest |

Each skill that backs a CD-P should add an activation cue near the top of its SKILL.md (one line): *"When asked to (re)build the Project bundle for this skill, load `/instruction-creator` alongside this skill and follow its `references/cd-project-bundle-guide.md`."*

## Scaffolding a new recipe (for skills without one yet)

When asked to set up a new Claude Desktop Project for a skill `<S>` that doesn't yet have a recipe:

1. Read `~/.claude/skills/<S>/SKILL.md` to understand the skill's purpose, scope, conditions, output discipline.
2. Audit `~/.claude/skills/<S>/references/` and `~/.claude/skills/<S>/templates/` for candidate knowledge files. Exclude: heavy PDFs, source-only files, internal-tooling docs.
3. Draft the **Custom Instructions** section in second-person voice — identity, primary subject matter, knowledge file references, what the Project can/can't do, routing rules, output discipline.
4. Draft the **File Manifest** table — propose a flat layout, flag any collisions for rename.
5. Write the **Sync Log** with a single creation row.
6. Save to `~/.claude/skills/<S>/references/cd-project-recipe.md`.
7. Surface the draft to the user for review before running the generation procedure.

## What this guide is NOT for

- **Skill `.zip` uploads** to Claude Desktop Settings → Capabilities → Skills. See `claude-desktop-packaging-guide.md`.
- **Team-shared CD-T skills** on Fusang Claude Teams plan. See `claude-desktop-packaging-guide.md`.
- **Per-conversation Project content** edits inside Claude Desktop itself (those happen in the app, not by regenerating the bundle).

## Migration notes

Historically, some skills stored Project bundle material in a `project-desktop/` subdir (custom-instructions.md + README with re-zip block producing a `.zip` archive). That pattern is **deprecated** as of 2026-05. Migration:

1. Move the custom-instructions text into the recipe's **Custom Instructions** section.
2. Move the file-manifest table (with rename rules) into the **File Manifest** section.
3. Move the historical sync log into the **Sync Log** section.
4. Delete the `project-desktop/` subdir.
5. Update the skill's SKILL.md to remove any pointer to `project-desktop/` and add the activation cue line described above.

Reference implementation: `~/.claude/skills/medical/references/cd-project-recipe.md`.
